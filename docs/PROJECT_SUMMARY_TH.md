# สรุปโปรเจกต์ Pacman 0–2

ตรวจสถานะวันที่ 3 ตุลาคม 2026 โดยเทียบโค้ด เอกสาร ผลที่บันทึก และชุดส่งงาน

โปรเจกต์นี้เป็นงานเรียนวิชา Artificial Intelligence สำหรับสร้างเอเจนต์เล่น Pacman
บน engine ที่ดัดแปลงจาก UC Berkeley CS188 ครอบคลุมการค้นหาเส้นทาง
การตัดสินใจเมื่อมีคู่แข่ง และการประมาณสถานะที่มองไม่เห็นจากข้อมูลมี noise

## ทำอะไรไว้แล้ว

| ส่วน | เป้าหมายและวิธีที่ทำ | ไฟล์หลัก |
|---|---|---|
| Project 0 | กินอาหารทั้งหมดด้วย BFS และ A*; มี DFS สำหรับเปรียบเทียบ | `project0/bfs.py`, `astar.py`, `dfs.py` |
| Project 1 | กินอาหารและหลบผีด้วย Minimax และ H-Minimax | `project1/minimax.py`, `hminimax.py` |
| Project 2 | ประมาณตำแหน่งผีล่องหนด้วย Bayes filter แยก belief ของผีแต่ละตัว | `project2/bayesfilter.py` |
| โบนัส | เลือกการเดินตาม belief เพื่อไล่กินผี พร้อมเรียนรู้ทางเดินจาก legal actions | `project2/pacmanagent.py` |

**Project 0:** BFS หาเส้นทางจำนวนก้าวน้อยที่สุด ส่วน A* คิดต้นทุนจำนวนก้าว
รวมค่าปรับเมื่อกินแคปซูล ใช้ระยะทางจริงผ่านเขาวงกตและต้นไม้แผ่ทั่วขั้นต่ำของอาหาร
(MST) เป็น heuristic จึงอาจได้คะแนนดีกว่า BFS แม้ทั้งคู่ชนะ
ตัวอย่าง benchmark เดิมบนแผนที่ medium: BFS ขยาย 25,761 โหนด ได้ 565 คะแนน;
A* ขยาย 351 โหนด ได้ 568 คะแนน

**Project 1:** Minimax พิจารณาผีเป็นคู่แข่งที่เลือกทางเสียเปรียบที่สุดให้ Pacman
สร้างกราฟสถานะและแก้ค่าย้อนกลับเพื่อจัดการวงจร เหมาะกับแผนที่เล็ก
H-Minimax จำกัดความลึกเริ่มต้น 4 รอบ Pacman/ผี ใช้ alpha-beta pruning
และประเมินคะแนน อาหาร ระยะทาง อันตรายจากผี และการเดินซ้ำ เพื่อใช้กับแผนที่ใหญ่ขึ้น
ขอบเขตเอเจนต์ส่วนนี้คือผีหนึ่งตัวตามโจทย์

**Project 2:** ใช้แบบจำลองการเดินของผีและเซนเซอร์ระยะทางที่มี binomial noise
อัปเดตความน่าจะเป็นด้วย Predict → Correct → Normalize
รองรับผี `confused`, `afraid`, `scared` และหลายตัวในเกม
ผีที่ถูกกินแล้วมี belief เป็นศูนย์ ส่วน controller โบนัสใช้ belief ช่วยเลือกการเดิน
โดยไม่อ่านตำแหน่งจริงของผีมาเป็นข้อมูลตัดสินใจ

## งานสนับสนุนและสิ่งส่งมอบ

- `tests/`: ตรวจอัลกอริทึมเทียบ reference กรณีขอบ และ AST ของฟังก์ชันที่ห้ามแก้
- `scripts/benchmark.py`: รันเกมจริงแบบไม่มีหน้าต่าง 45 กรณี เก็บคะแนน เวลา และโหนด
- `project2/experiments.py`: ทดลอง 18 เงื่อนไขจาก 2 แผนที่ × 3 ชนิดผี × 3 variances
  เงื่อนไขละ 30 trials และ 3 ผี เก็บ entropy, Brier และช่วงความเชื่อมั่น
- `scripts/check_high_noise.py`: ตรวจเพิ่มเติมเฉพาะ confused ที่ variance 4 ถึง 27,000 steps
- `scripts/build_report.py`: สร้างรายงานจากผลทดลองและคอมไพล์ PDF
- `scripts/package_submissions.py`: จัด archive และตรวจเนื้อหาพร้อม SHA-256
- [รายงานภาษาอังกฤษ](../project2/report.pdf): 3 หน้า เว้นชื่อผู้จัดทำไว้
- [ชุดส่งงาน](../deliverables/README.md): Project 0 มี BFS/A*; Project 1 มี Minimax/H-Minimax;
  Project 2 มี Bayes filter, controller โบนัส และ PDF

ไฟล์ ZIP ที่ root เป็นชุดเริ่มต้น โค้ดที่ทำแล้วอยู่ใน `project0/`, `project1/`, `project2/`
และแต่ละโปรเจกต์มี engine ของตัวเอง จึงต้องใช้คำสั่งและ flags ให้ตรงส่วน

## สถานะและข้อจำกัด

ตรวจซ้ำวันที่ 3 ตุลาคม: **27 tests ผ่าน**, ตรวจรูปแบบโค้ดผ่าน
และ archive ทั้งสามชุดตรงกับไฟล์ปัจจุบันและ manifest
ผล benchmark ที่บันทึกวันที่ 30 กันยายนคือ **ชนะ 45/45 เกม**
โดยรอบตรวจเอกสารนี้ไม่ได้รันเกมและการทดลองยาวซ้ำ
รายละเอียดหลักฐานอยู่ใน [VALIDATION_TH.md](VALIDATION_TH.md)

ผลทดลองเดิมพบว่า entropy และ Brier ต่ำลงจาก confused ไป afraid และ scared
ในสองแผนที่ที่ทดลอง แต่ confused ที่ noise สูงยังไม่ผ่านเกณฑ์ความนิ่งของ entropy
แม้เพิ่มเป็น 27,000 steps จึงยังสรุปว่าเข้าสู่ equilibrium ไม่ได้
การทดลอง filter ใช้ Pacman อยู่นิ่งและไม่กินผี ส่วนเกมโบนัสที่เคลื่อนที่จริงตรวจแยกด้วย benchmark

งานหลักมีโค้ด ผลทดลอง รายงาน และชุดส่งครบแล้ว สิ่งที่ยังต้องตรวจหรือเติมก่อนส่งคือ:

1. ทดลองหน้าต่างเกมและ Tk บนเครื่องสมาชิก; ยังไม่มีผลยืนยัน Windows/macOS
2. ตรวจชื่อ/รหัสที่ต้องใส่ใน PDF ซึ่งปัจจุบันเว้นว่าง และข้อกำหนดกลุ่มสามคน
   กำหนดส่งและช่องทางส่งกับประกาศรายวิชา; README เก็บโจทย์เก่าบางส่วนไว้
3. สมาชิกแต่ละคนทบทวนและอธิบายโค้ดของตนได้; แนวแบ่งงานอยู่ในคู่มือ workflow
4. หากแก้อัลกอริทึม ให้ทดสอบและสร้างผลที่เกี่ยวข้องใหม่ก่อนสร้างรายงานและแพ็กงาน

ผลที่มีเป็น tests และแผนที่สาธารณะ ยังไม่ใช่คะแนนจากระบบตรวจส่วนตัวของอาจารย์
archive เป็นไฟล์เตรียมส่งในเครื่อง ยังไม่ได้ส่งงานอัตโนมัติ
