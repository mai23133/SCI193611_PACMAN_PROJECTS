## สไลด์ 1 — โจทย์และภาพรวม

**ขึ้นสไลด์:** ภาพเกม Pacman และคำว่า *Search → Adversarial search → State estimation*

**พูด:** “งานนี้สร้างเอเจนต์เล่น Pacman ผ่านปัญหา AI สามแบบที่ยากขึ้นตามข้อมูลที่เอเจนต์มี Project 0 รู้แผนที่และต้องหาเส้นทางกินอาหาร Project 1 มีผีที่ตอบโต้การเดินของเรา และ Project 2 มองไม่เห็นตำแหน่งผี จึงต้องใช้ข้อมูลเซนเซอร์ที่มีความคลาดเคลื่อนมาประมาณตำแหน่ง เป้าหมายของเราคือทำให้อัลกอริทึมทั้งสามส่วนทำงานในเกมจริง และตรวจผลด้วยการทดสอบและการทดลอง”

## สไลด์ 2 — Project 0: วางแผนเส้นทาง

**ขึ้นสไลด์:** ภาพแผนที่หนึ่งภาพ และตารางนี้

| วิธี | คะแนนบน `medium` | โหนดที่ขยาย |
|---|---:|---:|
| BFS | 565 | 25,761 |
| A* | 568 | 351 |

**พูด:** “ส่วนแรกไม่มีผี เราต้องหาเส้นทางกินอาหารทั้งหมด BFS ไล่สถานะตามจำนวนก้าว จึงเป็นตัวตั้งต้นที่เข้าใจง่าย ส่วน A* เลือกสำรวจสถานะจากต้นทุนที่เดินมาและการประมาณต้นทุนที่เหลือ เราใช้ระยะทางผ่านเขาวงกตและต้นไม้แผ่ทั่วขั้นต่ำของจุดอาหารมาช่วยประมาณ บนแผนที่ medium ในผลที่บันทึกไว้ A* ขยาย 351 โหนด เทียบกับ BFS 25,761 โหนด ทั้งสองวิธีชนะเกม คะแนนต่างกันเพราะ A* คิดค่าปรับของแคปซูลในต้นทุนด้วย”

**ชี้โค้ดเมื่อถูกถาม:** [`project0/bfs.py`](../project0/bfs.py), [`project0/astar.py`](../project0/astar.py) ส่วน DFS ใน [`project0/dfs.py`](../project0/dfs.py) ใช้เป็นวิธีเปรียบเทียบเพิ่มเติม

## สไลด์ 3 — Project 1: ตัดสินใจเมื่อมีผี

**ขึ้นสไลด์:** ต้นไม้ตัดสินใจสั้น ๆ ที่ Pacman เลือกค่าสูงสุดและผีเลือกค่าต่ำสุด

**พูด:** “เมื่อมีผี การเดินที่ดีที่สุดไม่ได้ขึ้นกับเส้นทางของ Pacman อย่างเดียว Minimax จึงพิจารณาทุกทางที่ผีเดินได้ แล้วเลือกการเดินที่รับมือกับกรณีเสียที่สุด งานนี้จัดการสถานะที่วนซ้ำด้วยการสร้างกราฟและแก้ค่าย้อนกลับ จึงใช้กับแผนที่เล็ก ส่วน H-Minimax จำกัดการมองล่วงหน้าเริ่มต้นที่ 4 รอบ ใช้ alpha-beta pruning เพื่อลดกิ่งที่ไม่จำเป็น และประเมินสถานะจากคะแนน อาหาร ระยะทาง และความเสี่ยงจากผี เพื่อเล่นแผนที่ใหญ่ขึ้น งานส่วนนี้ออกแบบตามโจทย์ที่มีผีหนึ่งตัว”

**ชี้โค้ดเมื่อถูกถาม:** [`project1/minimax.py`](../project1/minimax.py), [`project1/hminimax.py`](../project1/hminimax.py)

## สไลด์ 4 — Project 2: ตามหาผีที่มองไม่เห็น

**ขึ้นสไลด์:** แผนภาพ `belief เดิม → Predict → Correct ด้วยเซนเซอร์ → Normalize → belief ใหม่`

**พูด:** “ส่วนสุดท้าย Pacman มองไม่เห็นผี แต่มีเซนเซอร์วัดระยะทางที่มี noise เราจึงเก็บ belief หรือความน่าจะเป็นที่ผีแต่ละตัวอยู่ในแต่ละช่อง ทุกครั้งที่ผีอาจเคลื่อนที่ เราทำนายตำแหน่งใหม่ จากนั้นนำค่าที่เซนเซอร์อ่านได้มาปรับความน่าจะเป็น แล้วปรับผลรวมให้เป็นหนึ่ง วิธีนี้รองรับผีหลายตัวและพฤติกรรม `confused`, `afraid`, `scared` โบนัสคือเอเจนต์ที่ใช้ belief เลือกทางเดินไปกินผี โดยไม่ใช้ตำแหน่งจริงของผีในการตัดสินใจ”

**ชี้โค้ดเมื่อถูกถาม:** [`project2/bayesfilter.py`](../project2/bayesfilter.py), [`project2/pacmanagent.py`](../project2/pacmanagent.py)

## สไลด์ 5 — ผลการทดลองและการตรวจสอบ

**ขึ้นสไลด์:** [กราฟความไม่แน่นอนตามเวลา](../project2/results/convergence.png) หรือ [กราฟผลของ sensor variance](../project2/results/variance.png) พร้อมตัวเลข “45/45 เกม” และ “27 tests”

**พูด:** “เราทดสอบด้วยเกมจริงแบบไม่เปิดหน้าต่าง 45 กรณี และผลที่บันทึกวันที่ 30 กันยายน 2026 ชนะทั้งหมด 45 เกม การตรวจซ้ำวันที่ 3 ตุลาคมมี 27 tests ผ่าน ส่วน Bayes filter ทดลอง 18 เงื่อนไขจาก 2 แผนที่ 3 ชนิดผี และ 3 ระดับ noise เงื่อนไขละ 30 ครั้ง กราฟแสดงว่าในการทดลองนี้ belief มีความไม่แน่นอนต่ำลงเมื่อเปลี่ยนจากผี confused ไป afraid และ scared และ noise สูงขึ้นทำให้ความไม่แน่นอนช่วงท้ายสูงขึ้น”

**พูดข้อจำกัดต่อทันที:** “ผลทดลอง filter ใช้ Pacman อยู่นิ่งเพื่อให้เทียบเงื่อนไขกันได้ ส่วนการเล่นจริงที่ Pacman เคลื่อนที่ตรวจแยกใน benchmark สำหรับกรณี confused ที่ noise สูง แม้ทดลองเพิ่มถึง 27,000 steps ก็ยังไม่ผ่านเกณฑ์ความนิ่งของ entropy เราจึงไม่สรุปว่าเข้าสู่ equilibrium ผลทั้งหมดเป็นการทดสอบบนชุดที่มี ไม่ใช่คะแนนจากระบบตรวจส่วนตัวของอาจารย์”

## สไลด์ 6 — สาธิตและสรุป

เลือกสาธิต **หนึ่งเกม** ที่เครื่องใช้เวลาเหมาะกับช่วงนำเสนอ และเตรียมภาพผลจาก [ผลการตรวจสอบ](VALIDATION_TH.md) ไว้เผื่อเกมรันนาน คำสั่งด้านล่างเริ่มจากโฟลเดอร์รากของ repository และใช้ Python ใน environment ที่ติดตั้ง dependencies แล้ว:

```bash
cd project0
python run.py --agentfile astar.py --layout medium --silentdisplay
```

ถ้าต้องการโชว์ส่วนที่มีผีหรือ Bayes filter ใช้คำสั่งใดคำสั่งหนึ่งแทน โดยแต่ละโปรเจกต์มี flags ต่างกัน:

```bash
cd project1
python run.py --agent hminimax --ghost greedy --layout medium_adv --seed 42 --nographics
```

```bash
cd project2
python run.py --agentfile pacmanagent.py --bsagentfile bayesfilter.py --ghostagent scared --nghosts 3 --layout large_filter --sensorvariance 1 --seed 42 --silentdisplay
```

`--silentdisplay` และ `--nographics` ใช้แสดงผลใน terminal หากต้องการเปิดหน้าต่างเกม ให้เอา flag ดังกล่าวออกและตรวจว่าเครื่องมี Tk ก่อนวันนำเสนอ รายละเอียดการติดตั้งและคำสั่งอื่นอยู่ใน [คู่มือรันงาน](INSTALL_AND_RUN_TH.md)

**พูดปิด:** “งานนี้แสดงวิธีเลือกเครื่องมือ AI ให้ตรงกับข้อมูลที่มี: ใช้ search เมื่อรู้สถานะ ใช้ minimax เมื่อมีคู่แข่ง และใช้ Bayes filter เมื่อสถานะจริงมองไม่เห็น เราทำทั้งโค้ดเอเจนต์ การทดลอง รายงาน และชุดส่งงาน พร้อมบันทึกขอบเขตของผลทดสอบไว้ให้ตรวจซ้ำได้”

## คำถามที่อาจถูกถาม

- **ทำไม A* ขยายโหนดน้อยกว่า BFS?** เพราะ heuristic ช่วยจัดลำดับให้สำรวจสถานะที่มีแนวโน้มไปถึงเป้าหมายก่อน ตัวเลขที่ยกเป็นผลบนแผนที่ `medium` เท่านั้น
- **ทำไมไม่ใช้ Minimax เต็มบนแผนที่ใหญ่?** จำนวนสถานะเพิ่มมาก จึงใช้ H-Minimax จำกัดความลึกและประเมินสถานะปลายทาง
- **belief คืออะไร?** ตารางความน่าจะเป็นว่าผีอยู่ช่องใด โดยแต่ละตัวมี belief ของตัวเอง
- **entropy ต่ำแปลว่าอะไร?** filter กระจายความเชื่อในช่องน้อยลงหรือมั่นใจมากขึ้น แต่ควรดู Brier score ควบคู่เพื่อประเมินว่าความเชื่อนั้นตรงกับตำแหน่งจริงเพียงใด
- **ชนะ 45/45 หมายถึงใช้ได้กับทุกแผนที่หรือไม่?** หมายถึงชนะชุดกรณีที่บันทึกไว้เท่านั้น ยังไม่ครอบคลุมแผนที่ลับหรือระบบตรวจของอาจารย์
